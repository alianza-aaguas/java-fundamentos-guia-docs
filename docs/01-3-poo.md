## 3.1 Qué es la POO

La Programación Orientada a Objetos es un paradigma que organiza el software en objetos que combinan estado y comportamiento. En Java, la POO es central para modelar entidades del negocio.

### Diagrama conceptual

```text
Clase = plano
Objeto = instancia del plano
Atributos = estado
Métodos = comportamiento
```

---

## 3.2 Clase

### Definición técnica

Una clase es una plantilla o tipo definido por el desarrollador que describe atributos y comportamientos comunes a un conjunto de objetos.

### Definición para una persona no técnica

Es como el plano de una casa: define cómo será, pero todavía no es una casa construida.

### Caso de uso real

Una clase `Cliente` modela nombre, documento, email y operaciones como actualizar datos o calcular antigüedad.

### Ventajas

- Reutilización de estructura.
- Encapsula conceptos del negocio.
- Facilita mantenimiento.

### Desventajas o consideraciones

- Clases demasiado grandes violan la responsabilidad única.
- Puede haber sobreabstracción.

### Buenas prácticas

- Representar una sola responsabilidad principal.
- Usar nombres del dominio.

### Errores comunes

- Crear clases “Dios” con demasiadas responsabilidades.

### Ejemplo de código Java

```java
public class Cliente {
    String nombre;
    String email;

    void saludar() {
        System.out.println("Hola, soy " + nombre);
    }
}
```

### Explicación línea por línea

- `class Cliente`: define una plantilla.
- `String nombre`, `String email`: atributos.
- `void saludar()`: comportamiento.

### Pregunta de entrevista

¿Qué diferencia hay entre clase y objeto?

### Respuesta esperada

La clase es la plantilla; el objeto es la instancia concreta creada a partir de esa plantilla.

## 3.3 Objeto

### Definición técnica

Un objeto es una instancia de una clase con identidad, estado y comportamiento.

### Definición sencilla

Si la clase es el plano, el objeto es la casa construida.

### Caso real

Cada cliente registrado en el sistema es un objeto distinto de la clase `Cliente`.

### Ejemplo de código Java

```java
public class ObjetoEjemplo {
    public static void main(String[] args) {
        Cliente cliente = new Cliente();
        cliente.nombre = "Ana";
        cliente.saludar();
    }
}

class Cliente {
    String nombre;
    void saludar() {
        System.out.println("Hola, soy " + nombre);
    }
}
```

### Explicación

- `new Cliente()`: crea el objeto.
- `cliente.nombre = "Ana"`: asigna estado.
- `cliente.saludar()`: ejecuta comportamiento.

### Pregunta de entrevista

¿Qué significa instanciar una clase?

### Respuesta esperada

Crear un objeto concreto basado en la clase.

## 3.4 Atributos

### Definición técnica

Son variables que representan el estado de un objeto.

### Definición sencilla

Son las características del objeto, como color, nombre o saldo.

### Caso real

Un `CuentaBancaria` puede tener saldo, número y titular.

### Ejemplo

```java
class CuentaBancaria {
    private String numero;
    private double saldo;
}
```

### Buenas prácticas

- Hacerlos privados.
- Validar sus valores.

### Errores comunes

- Exponerlos públicamente sin control.

---

## 3.5 Métodos

### Definición técnica

Son funciones definidas dentro de una clase que representan comportamientos del objeto.

### Definición sencilla

Son acciones que el objeto puede hacer.

### Caso real

`depositar`, `retirar`, `calcularSaldo`.

### Ejemplo

```java
class CuentaBancaria {
    private double saldo;

    void depositar(double monto) {
        saldo += monto;
    }
}
```

### Pregunta

¿Por qué los métodos deben representar comportamientos?

### Respuesta

Porque encapsulan lógica relacionada con el estado del objeto.

## 3.6 Encapsulamiento

### Definición técnica

Ocultar el estado interno de un objeto y exponer acceso controlado mediante métodos.

### Definición sencilla

Es como una caja fuerte: no ves todo por dentro, solo puedes interactuar por mecanismos permitidos.

### Caso de uso real

Evitar que el saldo de una cuenta se modifique sin validación.

### Ventajas

- Protege integridad.
- Facilita validaciones.
- Reduce acoplamiento.

### Desventajas

- Más código inicial.

### Buenas prácticas

- Atributos privados.
- Getters/setters solo cuando aportan valor.
- Validaciones en mutadores.

### Ejemplo de código Java

```java
class Cuenta {
    private double saldo;

    public void depositar(double monto) {
        if (monto > 0) {
            saldo += monto;
        }
    }

    public double getSaldo() {
        return saldo;
    }
}
```

### Explicación

- `private double saldo`: no se modifica directamente.
- `depositar`: controla el cambio.
- `if (monto > 0)`: valida la operación.
- `getSaldo`: expone lectura segura.

### Pregunta de entrevista

¿Por qué encapsular?

### Respuesta

Para proteger el estado interno y controlar cómo se modifica.

## 3.7 Herencia

### Definición técnica

Mecanismo por el cual una clase hija reutiliza atributos y métodos de una clase padre.

### Definición sencilla

Es como heredar características familiares.

### Caso de uso real

`Empleado` y `Cliente` pueden compartir datos de una entidad persona.

### Ejemplo

```java
class Animal {
    void comer() {
        System.out.println("Comiendo");
    }
}

class Perro extends Animal {
    void ladrar() {
        System.out.println("Guau");
    }
}
```

### Pregunta

¿Cuándo conviene usar herencia?

### Respuesta

Cuando existe una relación real de especialización “es un” y el comportamiento compartido es coherente.

## 3.8 Polimorfismo

### Definición técnica

Capacidad de usar una misma referencia para representar diferentes comportamientos según el tipo concreto del objeto.

### Definición sencilla

Es como un control remoto que funciona con distintos aparatos, pero cada uno responde a su manera.

### Caso de uso real

Distintos métodos de pago implementan una misma operación `pagar()`.

### Ejemplo de código Java

```java
class Pago {
    void procesar() {
        System.out.println("Procesando pago");
    }
}

class PagoTarjeta extends Pago {
    @Override
    void procesar() {
        System.out.println("Procesando pago con tarjeta");
    }
}

public class PolimorfismoEjemplo {
    public static void main(String[] args) {
        Pago pago = new PagoTarjeta();
        pago.procesar();
    }
}
```

### Pregunta

¿Cuál es la diferencia entre polimorfismo estático y dinámico?

### Respuesta

El estático ocurre en compilación mediante sobrecarga; el dinámico ocurre en ejecución mediante sobrescritura.

## 3.9 Abstracción

### Definición técnica

Consiste en modelar lo esencial del objeto y ocultar detalles innecesarios.

### Definición sencilla

Es enfocarse en lo importante y dejar fuera lo que no hace falta ver.

### Caso de uso real

Una interfaz de pago muestra `pagar()`, pero oculta el detalle de integración con cada proveedor.

### Ejemplo

```java
abstract class Figura {
    abstract double area();
}
```

### Pregunta

¿Qué aporta la abstracción?

### Respuesta

Simplifica el diseño y permite trabajar con conceptos de alto nivel.

---

## 3.10 Interfaces

### Definición técnica

Contrato que define comportamientos que una clase debe implementar.

### Definición sencilla

Es una promesa: “si me implementas, podrás hacer esto”.

### Caso de uso real

`Repositorio<T>` para distintos motores de persistencia.

### Ejemplo

```java
interface Notificable {
    void notificar();
}
```

### Pregunta

¿Cuándo usarías una interfaz?

### Respuesta

Cuando quieres definir un contrato común para distintas implementaciones.

---

## 3.11 Clases abstractas

### Definición técnica

Clase que no puede instanciarse y puede combinar métodos abstractos y concretos.

### Definición sencilla

Es una base incompleta que obliga a completar ciertas partes en las hijas.

### Caso de uso real

Una clase base `Documento` con comportamiento común y validaciones compartidas.

### Ejemplo

```java
abstract class Documento {
    abstract void imprimir();
}
```

### Pregunta

¿Diferencia principal con una interfaz?

### Respuesta

La clase abstracta puede compartir estado y comportamiento base; la interfaz define un contrato más flexible.

---

## 3.12 Asociación

Relación general entre objetos que colaboran entre sí sin dependencia fuerte de ciclo de vida.

### Caso

Un `Profesor` está asociado a un `Curso`.

---

## 3.13 Agregación

Relación todo-parte débil; la parte puede existir sin el todo.

### Caso

Un `Equipo` tiene `Jugadores`, pero los jugadores pueden existir por separado.

---

## 3.14 Composición

Relación todo-parte fuerte; la parte depende del ciclo de vida del todo.

### Caso

Una `Casa` compuesta por `Habitacion`.

## 3.15 Tabla comparativa POO

| Concepto | Qué es | Ejemplo | Observación |
|---|---|---|---|
| Clase | Plantilla | `Cliente` | Define estructura |
| Objeto | Instancia | `new Cliente()` | Tiene identidad |
| Encapsulamiento | Ocultar/proteger | `private saldo` | Control del acceso |
| Herencia | Reutilización “es un” | `Perro extends Animal` | Usar con cuidado |
| Polimorfismo | Un tipo, múltiples comportamientos | `Pago pago = new PagoTarjeta()` | Clave en diseño flexible |
| Abstracción | Simplificar lo esencial | `abstract class Figura` | Oculta detalles |
| Interface | Contrato | `Notificable` | No comparte estado por defecto |
| Clase abstracta | Base parcial | `Documento` | Puede tener lógica común |
| Asociación | Colaboración | `Profesor`-`Curso` | Débil |
| Agregación | Todo-parte débil | `Equipo`-`Jugador` | Parte independiente |
| Composición | Todo-parte fuerte | `Casa`-`Habitacion` | Parte dependiente |

## 3.16 Conclusiones y buenas prácticas

La POO en Java permite modelar el negocio de forma más natural y mantenible. La clave no es usar todas las características porque sí, sino elegir la abstracción correcta para cada problema.

### Buenas prácticas generales

- Prioriza composición sobre herencia cuando tenga sentido.
- Encapsula el estado.
- Usa interfaces para desacoplar implementaciones.
- Modela con nombres del dominio real.
- Evita clases gigantes.
